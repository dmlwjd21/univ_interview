# 대입 면접 기출 아카이브

고3 학생이 **대학 → 학과 → 전형**을 고르면 최근 학년도 면접 기출문항이 **출처와 함께** 나오는 웹앱입니다.
전국 4년제 대학과 전문대학을 모두 목록에 담았습니다.

## 지금 들어 있는 것

| 항목 | 수량 |
| --- | --- |
| 대학 | 4년제 217개교 · 전문대 137개교 |
| 면접 기출문항 | 2,221문항 (64개교) |
| 원문 보고서 | 153건 (2025·2026학년도) |
| 면접 준비 가이드 | 245꼭지 |
| 입시결과 | 인증키 등록 후 수집 (아래 참고) |

문항마다 원문 PDF의 **쪽 번호**가 붙어 있어 `출처 원문 p.37 ↗` 를 누르면 그 쪽이 바로 열립니다.

## 기출문항은 어디서 오는가

핵심은 **선행학습 영향평가 결과보고서**입니다.

「공교육 정상화 촉진 및 선행교육 규제에 관한 특별법」 제10조에 따라, 대학별고사(논술·면접·실기)를
치른 모든 대학은 그 문항이 고교 교육과정을 벗어났는지 스스로 점검해 매년 공개해야 합니다. 이 보고서에는
**실제 출제 문항 · 출제 의도 · 교육과정 연계**가 함께 실립니다. 면접 기출의 1순위 자료인데도 가장 덜
알려져 있습니다.

수집 경로는 두 가지입니다.

1. 시·도교육청 대입정보 CDN 미러 — 학교 이름으로 주소가 정해져 빠르게 훑을 수 있습니다.
2. 각 대학 입학처 — 미러에 없는 학교는 앱에서 검색 경로를 안내합니다.
   (입학처 검색창에 `선행학습` 만 넣는 것이 가장 빠릅니다.)

## 면접 후기

수만휘 같은 입시 카페와 블로그 글로 가는 **검색 딥링크**를 대학·학과에 맞춰 만들어 줍니다.
"면접 후기 / 면접 복기 / 면접 질문"처럼 표현을 여러 각도로 바꿔 걸어 두는데, 후기 글은 제목이
제각각이라 한 가지 검색어로는 잘 걸리지 않기 때문입니다. **키가 필요 없습니다.**

네이버 검색 API 는 2026년 NAVER API HUB(네이버 클라우드 플랫폼)로 이관되면서 결제수단 등록이
필요해졌습니다. 후기 검색은 부가 기능이라 결제 계정을 요구하지 않는 쪽을 기본으로 두었고,
키가 있는 환경에서만 목록을 화면 안에 함께 띄웁니다.

어느 경우든 카페 본문을 직접 수집하지 않습니다. 로그인이 필요하고 이용약관에도 어긋나기 때문입니다.

## 시작하기

```bash
npm install
npm run dev
```

`http://localhost:3000` 에서 열립니다. 데이터는 저장소에 들어 있어 키 없이도 바로 동작합니다.

### 환경변수

`.env.example` 을 `.env.local` 로 복사해 채웁니다. 모두 선택 사항이고, 없으면 그 기능만 대체 동작합니다.

| 변수 | 쓰임 | 없을 때 |
| --- | --- | --- |
| `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET` | 후기 목록을 화면 안에 표시 | 딥링크만 표시 (기본) |
| `DATA_GO_KR_KEY`·`DATA_GO_KR_ENDPOINT` | 입시결과 수집 | 입결 수집 건너뜀 |
| `OPENAI_API_KEY` 또는 `ANTHROPIC_API_KEY` | 기출 추출 정확도 향상 | 규칙 기반으로만 추출 |

## 데이터 갱신

```bash
npm run data:universities   # 전국 대학·전문대 목록
npm run data:reports        # 선행학습 영향평가 보고서 찾기
npm run data:parse          # 보고서 PDF → 기출문항  (python, pymupdf 필요)
npm run data:tips           # 면접 지도 자료 → 준비 가이드
npm run data:adiga          # 입시결과
npm run data:validate       # 데이터 검증
npm run data:all            # 위 과정을 순서대로
```

`.cache/` 에 내려받은 PDF와 응답이 남아 두 번째 실행부터는 훨씬 빠릅니다.

### 추출 정확도

기본은 규칙 기반입니다. 문서를 면접/논술/실기 구획으로 나누고, 줄바꿈으로 쪼개진 문장을 다시 이어 붙인
뒤, **문장이 의문형·명령형으로 끝나는 것**만 문항으로 받습니다. 그래도 대학마다 서식이 달라 평가요소
표나 운영 문서가 일부 섞입니다.

LLM 보정을 켜면 문항이 온전해지고 학과·전형이 훨씬 잘 채워집니다.

```bash
OPENAI_API_KEY=sk-... python scripts/collect/parse_reports.py --llm
```

일부 대학만 다시 뽑을 때는 `--only` 와 `--merge` 를 함께 씁니다. 나머지 대학은 기존 결과를 그대로 둡니다.

```bash
python scripts/collect/parse_reports.py --llm --merge --only 고려대학교,성균관대학교
```

**쪽 번호 처리** — LLM 은 원문 쪽 번호를 모릅니다. 그래서 돌려받은 문항의 글자를 원문 페이지에서 되찾아
실제 쪽 번호를 붙입니다(`locate_page`). 학생이 "정말 이 대학이 물어본 게 맞나"를 원문으로 확인할 수
있어야 하므로 이 값은 뭉뚱그리지 않습니다.

**제시문 분리** — 제시문 기반 면접은 (가)(나)(다) 지문이 먼저 나오고 물음이 뒤따릅니다. 이것을 한 칸에
합치면 정작 답해야 할 물음이 긴 지문에 묻히므로 `question` 과 `passage` 를 따로 저장하고, 화면에서는
제시문을 접어 둡니다.

### 자동 갱신

`.github/workflows/update-data.yml` 이 보고서 공개 시기(3~5월)에 맞춰 돌면서 수집 → 검증 → 빌드를
거친 뒤 **Pull Request** 를 엽니다. 자동으로 main 에 밀어 넣지 않습니다. 잘못 추출된 데이터가 그대로
배포되면 학생이 틀린 정보를 보게 되기 때문입니다.

저장소 Settings → Secrets 에 `OPENAI_API_KEY`, `DATA_GO_KR_KEY`, `DATA_GO_KR_ENDPOINT` 를 넣으면
워크플로가 함께 사용합니다.

## 잘못된 데이터 고치기

자동 수집이라 틀린 값이 들어올 수 있습니다. `data/overrides/universities.json` 이 보정 레이어입니다.

```json
{
  "add": [{ "name": "서울대학교", "type": "university", "region": "서울" }],
  "patch": { "연세대학교": { "region": "서울" } },
  "remove": ["육군사관학교 교수부"]
}
```

수집 스크립트를 다시 돌려도 이 파일의 값이 항상 이깁니다.

## 배포

Vercel 에 저장소를 연결하면 별도 설정 없이 배포됩니다. 데이터가 JSON 파일이라 DB가 필요 없고,
대학별 페이지는 빌드 시점에 정적으로 만들어집니다.

## 구조

```
app/                  화면 (Next.js App Router)
  univ/[id]/          대학별 기출·입결·후기
  api/reviews/        네이버 검색 API 연동
components/           검색 패널, 문항 브라우저, 후기 검색
lib/                  타입과 데이터 접근
data/                 수집 결과 JSON (커밋됨)
  overrides/          사람이 고치는 보정 레이어
scripts/              수집·파싱·검증
```

## 한계

- 기출이 모인 학교는 아직 64곳입니다. 나머지는 앱이 안내하는 검색 경로로 원문을 직접 찾아야 합니다.
- 면접을 서류 확인 위주로 운영하는 대학은 보고서에 "정형화된 문항이 없다"고만 적습니다. 문항이 없는
  것이 아니라 **정해진 문항이 없다**는 정보입니다. 그런 학교는 학생부 숙지가 전부입니다.
- 학과·전형 분류는 문맥으로 추정한 값이라 비어 있거나 틀릴 수 있습니다. 표시된 **출처 원문이 언제나
  기준**입니다.
